# Качество распознавания русского — GigaAM на CPU

Отчёт: **оценка качества русского** воспроизводимым мини-бенчмарком (WER/CER),
сравнение вариантов модели, замер скорости (RTF) и RAM на референсном CPU, вывод
о пригодности для диктовки.

## TL;DR

- GigaAM v3 на русском **очень хорош**: на чистой читаной речи **WER ≈ 5–6 %,
  CER ≈ 1.3 %**. Половина клипов распознаётся **дословно** (WER = 0).
- Основные ошибки — **редкие имена собственные, иностранные транслитерации,
  аббревиатуры/единицы** (pH, индийские/испанские имена). На обычной речи ошибок
  почти нет; низкий CER подтверждает, что это near-miss в паре букв, а не «каша».
- На этом CPU (i7-8750H, 6 ядер) инференс идёт в **9–11× быстрее реального
  времени**. Для интерактивной диктовки клип 5–15 с обрабатывается за **~0.5–1.7 с**
  → **годится для диктовки**.
- **Рекомендация:** для лучшего качества русского — **`v3_e2e_rnnt`** (WER 4.9 %),
  запаса по скорости на CPU достаточно. `v3_e2e_ctc` — чуть быстрее, чуть слабее,
  разумный дефолт. `v3_ctc` (без пунктуации) — только если нужна максимальная
  простота вывода.

## Результаты

Хост: **Intel Core i7-8750H** (6 ядер / 12 потоков, 2.2 ГГц), 64 ГБ RAM, **без GPU**.
Набор: **30 клипов Google FLEURS `ru_ru` (test)**, 6.2 мин чистой читаной речи,
16 kHz mono. Единая нормализация reference/гипотезы (нижний регистр, ё→е, снятие
пунктуации, числа→слова). Корпусные WER/CER (конкатенация). RTF = время
обработки / длительность аудио (меньше — лучше). RAM — RSS контейнера с загруженной
моделью в простое.

| Модель | WER | CER | RTF (обработка/аудио) | Скорость | RAM (загружена) | Клипов | Аудио |
|---|---|---|---|---|---|---|---|
| `v3_e2e_rnnt` | **4.9 %** | 1.3 % | 0.111 | 9.0× | 1.44 GiB | 30 | 374.3 с |
| `v3_e2e_ctc`  | 6.2 % | 1.3 % | 0.088 | 11.3× | 1.41 GiB | 30 | 374.3 с |
| `v3_ctc`      | 8.3 % | 2.2 % | 0.091 | 10.9× | 1.42 GiB | 30 | 374.3 с |

- **Качество:** `rnnt` заметно лучше по WER (4.9 % против 6.2 % у `ctc`), CER у
  обоих e2e ≈ 1.3 %. Вариант без пунктуации `v3_ctc` ощутимо хуже (8.3 % / 2.2 %).
- **Скорость:** все варианты — быстрее реального времени в ~9–11 раз. RNNT
  ~на 25 % медленнее CTC (авторегрессивное декодирование), но всё ещё 9×.
- **RAM:** ~1.4 GiB на загруженную модель — при 64 ГБ запас огромный.
- **Пунктуация:** `v3_e2e_*` расставляют пунктуацию и нормализуют текст
  (числа цифрами) прямо в выводе. `v3_ctc` — сплошной текст без пунктуации.

## Латентность для диктовки

Для короткого диктовочного клипа задержка ≈ `RTF · длительность + сетевой оверхед`:

| Длительность клипа | `v3_e2e_ctc` (~0.09) | `v3_e2e_rnnt` (~0.11) |
|---|---|---|
| 2 с  | ~0.2 с | ~0.2 с |
| 5 с  | ~0.5 с | ~0.6 с |
| 15 с | ~1.3 с | ~1.7 с |

Обе модели дают ответ за **менее ~2 с** на типичных диктовочных клипах →
интерактивно комфортно. Разница между ctc и rnnt по латентности незначима, поэтому
для диктовки выигрывает более точный `rnnt`. Модель держится «тёплой»
(`MODEL_IDLE_TIMEOUT=0`), так что задержки первого запроса нет.

## Где проседает (анализ ошибок)

**16 из 30** клипов у обеих e2e-моделей — WER = 0 (дословно). Почти весь WER даёт
горстка клипов с редкими сущностями:

- **Экзотические имена собственные / транслитерации.** Худший клип (`fleurs_021`):
  «Лаккха Сингх исполнил чхаппан бхог бхаджан» → «Лакха Синг… Чхаббан Бхоп Хаджан».
  Топонимы: «Кочамо/Йосмит» → «Качама/ол Смит».
- **Аббревиатуры и единицы.** «pH» → «PH», «H в pH» → «HPH».
- **Составные числительные с дефисом.** «53-летний» модель произносит словом
  («пятидесятитрёхлетний»); из-за нормализации «53» → «пятьдесят три» это частично
  **артефакт метрики** (см. оговорку ниже), а не чисто акустическая ошибка.

Вывод: на **обычной русской речи** (диктовка, разговорная речь, новости) модель
практически безошибочна; деградация локализована на **редких именах, иностранных
словах, аббревиатурах**. Низкий CER (≈1.3 %) подтверждает, что даже «ошибочные»
клипы распознаны близко к тексту.

## Оговорки по методике

- **Класс записей.** FLEURS — чистая **читаная** речь (студийная). Это верхняя
  граница качества. Для реального разговорного/шумного аудио WER будет выше — чтобы
  это измерить, добавьте свои «боевые» записи (см. ниже) с эталонами.
- **Нормализация чисел.** Числа приводятся к словам для обеих сторон. Составные
  формы («53-летний», «2010-х») выравниваются неидеально и слегка завышают WER;
  реальная акустическая точность чуть выше заявленной.
- **Английский — вне фокуса.** GigaAM v3 обучена на русском; иностранные вставки
  ожидаемо распознаются плохо (см. смешанный RU/EN семпл в `sample-data/`).
- **Размер выборки.** 30 клипов — быстрый ориентир. Для более узкого доверительного
  интервала увеличьте набор: `make dataset FLEURS=100`.

## Как воспроизвести

```bash
make venv                    # .venv + tooling (один раз)
make dataset                 # 30 клипов FLEURS ru → benchmark/dataset/
make benchmark               # прогон 3 моделей → таблица + benchmark/results/*
```

Отдельные шаги:

```bash
# Свой набор клипов (число из FLEURS):
python benchmark/build_dataset.py --fleurs 100

# Прогон конкретной модели против уже запущенного сервиса:
python benchmark/run_benchmark.py --model v3_e2e_rnnt --out benchmark/results/rnnt

# Пересобрать сводную таблицу из results/:
python benchmark/aggregate.py
```

### Добавить «боевые» записи

Положить аудио (любой формат) в `benchmark/dataset/field/` и указать эталоны в
`benchmark/dataset/field/references.tsv` — по строке на файл:

```
my_clip_01.wav	полный эталонный текст записи
my_clip_02.ogg	другой эталонный текст
```

Затем `python benchmark/build_dataset.py` (можно с `--field-only`) и `make benchmark`.
Аудио автоматически приводится к 16 kHz mono.

## Артефакты

- Сырые прогоны: `benchmark/results/<model>.csv` (по клипам: ref, hyp, WER, CER, RTF).
- Сводки: `benchmark/results/<model>.summary.json`, `summary_table.md`.
- Раннеры: `benchmark/build_dataset.py`, `run_benchmark.py`, `run_all.sh`,
  `aggregate.py`; нормализация — `benchmark/normalize.py`.
