# Роадмап: gigaam-stt как публичный Docker-образ

Ресерч того, что разумно прикрутить к сервису в рамках цели «публичный образ
на Docker Hub: `docker run` → готовый русский ASR с админкой и API».
Дата: 2026-08-13. Полные результаты веб-ресерча (конкуренты, OpenAI API,
Docker Hub) — в [../RESEARCH_PUBLIC_IMAGE.md](../RESEARCH_PUBLIC_IMAGE.md).

## A. Возможности GigaAM, которые уже есть в vendored-пакете, но не выведены

### A1. Пословные таймстемпы — ✅ СДЕЛАНО (в ONNX-движке)
- Пакет умеет: `model.transcribe(wav, word_timestamps=True)` возвращает
  `TranscriptionResult(text, words)`; механика — `timestamps_utils.py`
  (`compute_frame_shift`, `frames_to_words`).
- В сервисе: OpenAI-раут уже принимает `timestamp_granularities` и передаёт
  `word_timestamps` в движок; схемы (`OpenAIWord`, `WordTimestamp`) готовы.
  Но тензорный путь инференса выбрасывает слова: в
  `src/asr/gigaam.py` (`_transcribe_audio_tensor`) из кортежа результата
  берётся только текст (`result = result[0]`).
- Что сделать: доставать `token_frames` из декодера и конвертировать в слова
  через `frames_to_words`; прокинуть в `verbose_json` (words/segments) и в
  нативный `json`. `srt`/`vtt` станут точнее (сейчас границы — чанки).

### A2. Эмоции: GigaAMEmo — ✅ СДЕЛАНО (`POST /gigaam/emotion` + WebUI)
- В пакете: класс `GigaAMEmo`, `get_probs(wav) -> {emotion: prob}`,
  загрузка `load_model("emo")` (веса ~в том же CDN).
- Идея: endpoint `POST /gigaam/emotion` (+ галочка на тестовой странице).
  Ни один из массовых whisper-серверов такого не даёт — отличительная фича
  для публичного образа.

### A3. ONNX-инференс — ✅ СДЕЛАНО (образ 733 МБ, веса на HF, деплой переключён)
Ресерч 2026-08-13 (все проверки в контейнере, на реальных весах):
- **Транскрипция**: `v3_e2e_ctc` конвертирован (`to_onnx` → 845 МБ fp32
  .onnx + yaml); ONNX-инференс даёт транскрипт **бит-в-бит** с torch;
  скорость сопоставима (1.21 c vs 0.94 c на 20-с клипе, ONNX без тюнинга
  тредов и без int8-квантизации).
- **Пословные таймстемпы**: работают на чистом ONNX-путе — кадры токенов
  извлекаются из CTC-выхода (argmax + схлопывание), `frames_to_words`
  торч-независим. Слова совпали с torch (расхождение ≤0.04 с).
- **Эмоции (GigaAMEmo)**: экспортируется и работает через onnxruntime,
  вероятности идентичны torch ({angry:0, sad:.001, neutral:.992, positive:.007}).
- **Фичи без torch**: написан `src/asr/features.py` (numpy log-mel,
  повторяет torchaudio MelSpectrogram): max diff 6.5e-4, транскрипт
  идентичен. Токенизатор — чистый sentencepiece (модель уже в томе).

Оставшиеся этапы миграции:
1. Engine-класс `GigaAMOnnxASR` (интерфейс ASRModel): numpy-фичи → ONNX
   encoder → numpy CTC-декод с кадрами → текст/слова; чанкование длинного
   аудио переиспользуется. RNNT — через vendored `_decode_rnnt_batch`
   (3 сессии), таймстемпы для RNNT — доработка записи кадров при эмите.
2. Endpoint эмоций `/gigaam/emotion` (+ страница).
3. Конвертация всех вариантов + **хостинг .onnx-весов** — ВОПРОС К
   ПОЛЬЗОВАТЕЛЮ: публичному образу нужен источник скачивания (HF Hub под
   своим аккаунтом? GitHub Releases?). Оригинальные .ckpt публичный образ
   конвертировать не сможет (нет torch). Вариант: fp16-экспорт (~420 МБ).
4. Новый Dockerfile: без torch/torchaudio, с onnxruntime (~50 МБ) —
   ожидаемый образ ~0.6–0.8 ГБ (сейчас 1.81).
5. Тюнинг: intra_op_num_threads (в vendored load_onnx захардкожено 8 —
   на 6 ядрах пересабскрайб), int8-квантизация как опция.
6. Полный прогон tests/ + бенчмарки скорости/качества, обновление README.

### A4. VAD-longform (pyannote) — средняя/большая, спорная ценность
- `transcribe_longform()`: сегментация по речи (VAD) + батчевый инференс
  сегментов. Точнее наших фиксированных 30-с чанков (нет разрезанных слов).
- Цена: зависимость pyannote.audio (тяжёлая, тянет torch-экосистему обратно)
  + HF_TOKEN у пользователя. Альтернатива: лёгкий VAD (silero-vad, ~2 МБ,
  ONNX) для умных границ чанков — та же идея без pyannote.

### A5. Прочее в пакете
- `embed_audio()` — SSL-эмбеддинги аудио (нишевое, пропустить).
- `task=translate` сейчас принимается и молча игнорируется — GigaAM не
  переводит; надо вернуть 400 или задокументировать.

## B. Ops/безопасность для «голого» `docker run` (без нашего nginx)

### B1. Блокировка event loop — ✅ ИСПРАВЛЕНО (asyncio.to_thread)
- Хендлеры `async def`, но внутри — синхронный `future.result(timeout=...)`
  (`src/services/timeout.py`). На время транскрипции замирает ВЕСЬ сервер:
  /health, страница, параллельные запросы.
- Фикс маленький: `await asyncio.to_thread(...)` или сделать хендлеры
  синхронными (FastAPI сам уведёт их в threadpool). Инференс на модель уже
  сериализован `model_lock` — конкурентность станет честной очередью.

### B2. Контейнер от root — ✅ ИСПРАВЛЕНО (uid 1000)
- В Dockerfile нет `USER`. Стандарт для публичных образов — непривилегированный
  пользователь + владение только `/app/data`.

### B3. Лимит размера загрузки — ✅ СДЕЛАНО (MAX_UPLOAD_MB → 413)
- У нас 200m стоит в nginx, но голый образ ничем не защищён: файл на гигабайты
  → OOM. Нужен env `MAX_UPLOAD_MB` + проверка Content-Length/стриминг.

### B4. CORS — ✅ СДЕЛАНО (CORS_ORIGINS)
- Браузерное приложение с другого origin не сможет звать API. Нужен env
  `CORS_ORIGINS` (по умолчанию выкл).

### B5. Очередь — ✅ СДЕЛАНО (MAX_PENDING_REQUESTS → 429)
- N параллельных запросов честно встанут в очередь на lock (после фикса B1),
  но копятся без предела: нужен настраиваемый предел очереди (429 при
  переполнении).

### B6. Мелочи
- Сравнение токена не timing-safe → `secrets.compare_digest` (1 строка).
- `/docs`, `/redoc`, `/openapi.json` всегда включены → env-флаг.
- Нет метрик (Prometheus `/metrics`: счётчики запросов, время, RTF, очередь).
- Лог-уровень не настраивается через env (`LOG_LEVEL`).

## C. OpenAI-совместимость (дополнится веб-ресерчем)

- `GET /v1/models` — многие клиенты (GUI, LangChain) энумерируют модели;
  у нас его нет, а реестр моделей уже есть — endpoint тривиален.
- `POST /v1/audio/translations` — GigaAM не переводит; корректный 501/400.
- Формат ошибок OpenAI (`{"error": {message, type, code}}`) — наши 4xx/5xx
  сейчас в формате FastAPI (`{"detail": ...}`), SDK парсят хуже.
- Streaming (SSE) транскрипции — появился у OpenAI (gpt-4o-transcribe);
  для длинных файлов можно отдавать чанки по мере готовности.
